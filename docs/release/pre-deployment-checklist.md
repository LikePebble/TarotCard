# Arca 배포 전 회귀 테스트

이 문서는 `main` 머지 전에 반드시 통과해야 하는 출시 게이트다. 자동 테스트만
통과해도 배포하지 않는다. 로그인 상태와 프리미엄 덱 소유 상태처럼 브라우저 저장소와
외부 인증에 따라 달라지는 흐름은 Preview에서 직접 확인한다.

## 1. 테스트 대상 고정

- [ ] PR의 head SHA를 기록한다.
- [ ] `.env`, PDF, 실험용 이미지·Lottie, 로컬 패키지 변경이 PR에 섞이지 않았는지 확인한다.
- [ ] 테스트·빌드·Preview가 모두 같은 head SHA를 가리키는지 확인한다.
- [ ] Vercel Preview 환경변수에 Supabase URL·anon key가 설정됐는지 확인한다.
- [ ] 결제 전 출시 검증이면 Preview에
      `NEXT_PUBLIC_ENABLE_RELEASE_TEST_TOOLS=true`를 설정한다.

## 2. 자동 검증

```bash
npm test
./node_modules/.bin/tsc --noEmit
git diff --check
npm run build
```

- [ ] 전체 Vitest가 통과한다.
- [ ] TypeScript 오류가 없다.
- [ ] `git diff --check`가 출력 없이 끝난다.
- [ ] 깨끗한 커밋 스냅샷에서 Next.js 빌드가 통과한다.
- [ ] 빌드 중 외부 폰트 DNS 오류가 나면 코드 오류와 구분하고 네트워크가 허용된
      환경에서 같은 SHA를 다시 빌드한다.

## 3. 프리미엄 덱 상태 회귀

월하비원과 K-POP 뮤즈버스에서 각각 수행한다.

### 미로그인·미소유

- [ ] 덱 상세는 0/78이고 프리미엄 카드가 모두 잠겨 있다.
- [ ] `기본 덱 설정하고 리딩받기`와 `로그인하고 카드 수집하기`만 보인다.
- [ ] 리딩 CTA가 중간에 `지금 리딩받기`로 바뀌지 않고 바로 `/reading`으로 이동한다.
- [ ] 리딩 화면의 카드 뒷면이 방금 선택한 프리미엄 덱 자산이다.
- [ ] 게스트 리딩 기록은 로그인 전까지 수집 수·해금·새 카드 닷에 반영되지 않는다.
- [ ] 모달에 올바른 800×1360 커버, 헤드라인, 소개 2개, 혜택 3개가 보인다.
- [ ] 가격 미지정 덱에는 가격과 구매 버튼이 없다.

### 로그인·미소유

- [ ] 기본 덱이면 `지금 리딩받기`, 아니면 `기본 덱 설정하고 리딩받기`가 보인다.
- [ ] 비활성 `모든 카드 해금하기` 버튼이 보이며 준비 중임이 접근성 이름에 포함된다.
- [ ] 로그인 전 대기 기록과 로그인 후 새 리딩에서 만난 카드만 도감에서 열린다.
- [ ] 만나지 않은 카드는 뒷면으로 유지된다.

### 출시 테스트 지급 후

- [ ] 개발자 로그인 또는 실제 로그인 상태에서 검증한다.
- [ ] 컬렉션 하단에 `출시 테스트 도구`가 보인다.
- [ ] `테스트 지급`을 누르면 해당 덱이 78/78로 바뀐다.
- [ ] 지급 즉시 만나지 않은 카드를 포함한 78장 전체 아트가 열린다.
- [ ] 드로우 화면의 카드 뒷면이 선택한 프리미엄 덱 자산이다.
- [ ] 덱 상세 카드 아트와 도감 링크가 정상적으로 열린다.
- [ ] 덱 상세에는 리딩 CTA 한 개만 보인다.

### 테스트 소유권 회수

- [ ] 기본 덱인 프리미엄 덱을 `테스트 회수`해도 리딩 선택은 유지된다.
- [ ] 회수한 덱은 만난 카드만 열린 상태로 돌아간다.
- [ ] 회수 뒤에도 프리미엄 덱 리딩은 계속 가능하다.

## 4. 계정 상태 회귀

### 미로그인

- [ ] MY 계정 카드에는 소셜 버튼이 직접 펼쳐지지 않는다.
- [ ] `로그인하러 가기` CTA가 `/login`으로 이동한다.
- [ ] 로그인 페이지에서 카카오·Google 버튼과 게스트 이용 안내가 보인다.

### 로그인

- [ ] OAuth 복귀 후 `/my`로 이동한다.
- [ ] MY 계정 카드에 이메일과 로그인 제공자(카카오/Google)가 보인다.
- [ ] 동기화 상태 또는 마지막 동기화 시간이 보인다.
- [ ] 로그아웃 버튼은 최소 44px 높이이며 처리 중 중복 클릭이 막힌다.
- [ ] 로그아웃 성공 후 MY가 미로그인 CTA로 바뀌고 계정 로컬 캐시가 비워진다.
- [ ] 로그아웃 네트워크 실패 시 오류 안내가 보이고 로컬 기록은 유지된다.

## 5. 핵심 사용자 흐름

- [ ] 오늘의 카드에 `하루 1회`, 과거·현재·미래에 `주 1회`가 보인다.
- [ ] 3장 설명에 이번 주의 과거·현재·미래 흐름임이 명시된다.
- [ ] 리딩 결과 → 카드 상세 → 뒤로 가기가 원래 리딩으로 돌아간다.
- [ ] 카드 상세에서 컬렉션으로 진입한 경우에는 컬렉션 컨텍스트로 돌아간다.
- [ ] 현재 주기 리딩 리셋 도구가 출시 테스트 플래그에서만 보인다.
- [ ] 3카드 팬에서 보이는 카드를 누르면 같은 카드가 선택되며 뒤 카드가 대신 선택되지 않는다.
- [ ] 메이저·각 수트 필터가 URL에 유지되고 카드 상세에서 뒤로 이동하면 같은 필터로 돌아간다.
- [ ] 새 카드 닷은 덱명·필터·카드명 우측 위에만 보이고 카드 상세를 열면 사라진다.

## 6. 반응형·접근성

- [ ] 375×812에서 홈, 컬렉션, MY, 덱 모달에 가로 스크롤이 없다.
- [ ] 1440px에서 로고·히어로·덱 카드·계정 카드 정렬이 안정적이다.
- [ ] 홈 히어로의 촛불 광원이 사진 전체가 아닌 불꽃 주변에서만 은은하게 일렁인다.
- [ ] 홈 히어로 이미지의 상하좌우가 배경으로 자연스럽게 페더링되고 카드 중앙은 선명하다.
- [ ] `prefers-reduced-motion: reduce`에서 촛불 모션이 정지하고 정적 광원만 유지된다.
- [ ] 모든 주요 CTA와 닫기/로그아웃 버튼은 44×44px 이상이다.
- [ ] 모달은 Escape로 닫히고 처음 포커스와 닫힌 뒤 포커스가 올바르다.
- [ ] 키보드만으로 로그인 CTA, 덱 지급, 리딩 CTA, 덱 인포 버튼, 로그아웃에 접근할 수 있다.
- [ ] 브라우저 콘솔에 새 오류가 없다.

## 7. Preview 승인과 운영 확인

- [ ] Vercel Preview 체크가 성공한 뒤에만 PR을 Ready 상태로 둔다.
- [ ] 위 수동 시나리오의 미소유·소유·미로그인·로그인 네 상태를 모두 확인한다.
- [ ] 승인된 head SHA가 움직이지 않았는지 다시 확인한 뒤 squash merge한다.
- [ ] `main`의 Vercel Production 체크가 성공할 때까지 추적한다.
- [ ] 운영 주소에서 HTTP 200, `아르카 | Arca`, 로고·히어로·덱 커버 자산을 확인한다.
- [ ] 운영에서 계정과 프리미엄 덱 핵심 흐름을 한 번 더 스모크 테스트한다.
