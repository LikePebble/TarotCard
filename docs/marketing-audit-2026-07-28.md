## 1. 결정적 발견 5가지 (2026-07-28 실행 **전** 스냅샷 — §0.5 참조)

### ① 카드 상세 234페이지가 완전 고아 — 최우선

```
src/app/collection/[deckId]/page.tsx:250
    return collected ? (<Link href={...}>) : (<div>)
```
`collected`는 `catalogCardUnlocked(owned, encounters, slug)`이고,
비로그인 방문자는 `collection-access.ts:9`가 `{owns:false, encounters:new Set()}`를 반환 → **항상 false**.

**실측**: `/collection/classic` HTML에서 `href="/collection/*/*"` → **0건**.

즉 크롤러는 카드 페이지로 가는 링크를 하나도 볼 수 없습니다. sitemap도 404이므로
**발견 경로가 물리적으로 존재하지 않습니다.** 홈에서 링크를 따라 도달 가능한 URL은 약 9개.
색인 가능 자산의 **96%가 크롤 그래프 밖**입니다.

> 두 워커의 상반돼 보이는 결론은 둘 다 맞습니다.
> **URL을 직접 치면 전문이 나옵니다**(게이팅 없음, GPTBot·PerplexityBot 200 실측).
> 그런데 **아무도 그 URL을 찾을 수 없습니다**(내부 링크 0 + sitemap 없음).
> 문제는 "읽을 수 있느냐"가 아니라 "찾을 수 있느냐"입니다.

### ② 한국어 코퍼스의 75%가 URL을 갖지 못했다

| 구분 | 분량 | 크롤 가능 |
|---|---:|---|
| `ko.ts` 정방향 정본 | 10,002자 | ✅ |
| `lore/` 상징·서사·대응 | 28,043자 | ✅ |
| `reversed.ts` 역방향 | 11,745자 | ❌ |
| `reversed-focus.ts` (역×5주제, 390항목) | 43,150자 | ❌ |
| `ko-focus-*.ts` (정×5주제, 385항목) | 35,035자 | ❌ |
| `ko-positions.ts` / `reversed-positions.ts` | 22,326자 | ❌ |
| **합계** | **150,301자** | **25.3%만 노출** |

크롤 불가 112,256자의 **유일한 소비처가 `ReadingResult.tsx` 하나**입니다.
이건 `"use client"`이고, 표시 조건이 localStorage에 저장된 리딩 세션이며,
무료 사용자는 하루 1회만 뽑습니다. **3중 잠금**입니다.

### ③ 애널리틱스 전무 → 모든 개선의 효과 검증 불가

`gtag`/`@vercel/analytics`/`posthog`/`plausible`/`mixpanel`/`google-site-verification`
전수 grep **0건**. 프로덕션 HTML에도 분석 스크립트 0개.

지금은 유입도, 전환율도, LCP도, 이 계획의 성과도 **관측할 수단이 없습니다.**

### ④ 수익 경로가 구조적으로 0%

- `price` 미설정 → `DeckInfoModal.tsx:48`에서 **가격 행 자체가 렌더 안 됨** (오표기가 아니라 부재)
- `collection/[deckId]/page.tsx:178` → `disabled` + `title="결제 기능 준비 중"`
- 결제/체크아웃/가격 라우트 0개, PG·IAP 코드 0줄
- `/terms`, `/privacy` **부재** — 국내 전자상거래법상 결제보다 먼저 필요
- `adFree` SKU는 **읽는 곳이 0곳**이고 제거할 광고 자체가 없음
- `blockingReading()` 호출 3곳 전부 `maxDailySlots` 미전달 → **ad_free 3슬롯 미배선**

### ⑤ 홈 초기 페이로드 3.9MB 중 2.81MB가 폰트

**실측**: 홈 `rel=preload` woff2 **96개 = 2,950,700 B**.
`layout.tsx:8`이 `subsets:["latin"]`을 선언했는데도 나눔명조 한글 서브셋 93개가 preload됩니다.
`rel=preload`는 `unicode-range`를 무시하므로 브라우저의 지연 로딩이 완전히 무력화된 상태입니다.

이미지 파이프라인은 정상입니다(next/image, webp 89% 절감, priority 설정, alt 한글).
**성능 병목은 전적으로 폰트 하나입니다.**

#### 철회된 항목 — 카드 상세로 가는 내부 링크 (2026-07-28 결정)

1-1(도감 그리드에서 미수집 카드도 상세로 링크)과 그 후속(카드 상세의 이전/다음이
미수집 카드까지 순회)은 구현했다가 **원복했다.** 뒤집힌 카드를 눌러 해석이 다 보이면
수집이라는 행위가 의미를 잃는다는 판단이다. 대안으로 검토했던 **별도의 "78장 카드 의미"
색인 페이지도 제외**하기로 했다.

**그래서 감수하는 것**: 카드 상세 234페이지로 가는 **내부 링크가 0개**이고, 크롤
경로는 `sitemap.xml` 하나뿐이다. sitemap만으로 색인은 되지만 내부 링크가 없으면
페이지 권위가 흐르지 않아 순위에는 불리하다. 이 제약은 수집 UX를 지키기 위해
의도적으로 선택한 것이며, 나중에 뒤집고 싶다면 되돌릴 지점은 위 두 곳이다.

Phase 2에서 카드 상세 본문이 두터워지면 페이지 자체의 경쟁력으로 일부 상쇄된다.

### Phase 2 — 코퍼스 해방 (1~2주, 최대 ROI)

**새 글을 쓰지 않습니다. 이미 쓴 11만 자를 이미 있는 페이지에 붙입니다.**

`[slug]/page.tsx`에서 서버 렌더 추가:
`reversed[slug].ko` · `focusParagraphOf(f,slug)`×5 · `reversedFocusParagraphOf(f,slug)`×5 · `koPositions[slug]` · `reversedPositions[slug]`

동시에 헤딩 부여 (현재 **H2/H3가 0개**, 섹션이 `<summary>`로만 구분됨):

```
H1  바보 The Fool
H2  바보 카드의 의미 (정방향)
H2  바보 역방향 의미               ← 현재 URL 자체가 없는 구간
H2  주제별 해석
  H3 연애 · 일 · 자기이해 · 건강 · 금전  (각 정/역)
H2  카드 속 상징 / 카드 이야기 / 전통 대응
H2  이 카드가 스프레드에서 나왔다면  ← 과거·현재·미래 자리별
```

부수 조치:
- 신규 섹션에 `<details>` 접힘 금지 — 렌더링 기반 AI 에이전트에게는 접힌 상태로 보임
- 영어 원문은 하단 이동 또는 제거 (웹 표준 RWS 영문은 중복 콘텐츠)
- **`searchParams` 의존 제거** → 정적 생성 복구.
  실측 `cache-control: private, no-cache, no-store` / `x-vercel-cache: MISS`.
  `generateStaticParams`가 234개를 빌드하는데 **런타임에 무시되고 있음**. TTFB 0.45s → ~0.15s

**결과: 크롤 가능 한국어 38,045자 → 150,301자 (4배)**

### D1이 후속 작업에 미치는 영향
- 도감 그리드에서 **미수집 카드도 상세로 링크**해도 제품 의도와 충돌하지 않는다 (Phase 1-1의 근거)
- 가격 카피는 "이 덱을 소유하세요"가 아니라 **"1년 걸릴 수집을 지금 완성하세요"** 축으로 간다
- 단, 무료로도 도달 가능하다는 사실이 지불 의사를 누를 위험이 있으므로, 진행률 UI 옆 "즉시 완성" 오퍼(Phase 4)가 중요해진다

### D6이 안고 가는 위험

덱을 "수집 시간 단축권"으로 팔기로 한 D1과 정면으로 맞물린다. 78장 수집에 필요한
기대 뽑기 횟수는 쿠폰 수집가 문제로 약 385회다.

| 하루 티켓 | 78장 완성까지 |
|---|---|
| 1장 (종전) | 약 385일 |
| **2~3장 (D6)** | **약 128~193일** |
| 6장 전체 개방 | 약 64일 |

즉 프리미엄 덱의 "1년 걸릴 수집을 지금 완성하세요"라는 논리가 **4~6개월치로 줄어든다.**
전체 개방(6장)을 택하지 않은 이유가 이것이다. 결제를 붙일 때 가격 카피는 이 숫자를
전제로 다시 써야 한다.

2장으로 정한 것은 활성화와 수집 속도 사이의 절충이다. 1장은 첫 세션이 막다른 길이고,
6장은 덱 판매 논리를 무너뜨린다. 2장(로그인 3장)이면 첫 세션에 최소 두 주제를 볼 수
있으면서 완성까지 반년 가까이 남는다.

반대로 얻는 것: 첫 세션이 카드 한 장에서 끝나던 막다른 길이 사라지고, 780개나 써 둔
주제별 해석문이 실제로 소비된다. 그리고 로그인 +1이라는 명확한 계정 전환 동기가 생긴다.

리롤 위험은 없다. `slotState`가 같은 테마를 다시 뽑으면 `completed`로 기존 결과를
돌려주므로, 티켓을 늘려도 "마음에 드는 답이 나올 때까지 뽑기"는 불가능하다.

**측정 주의**: 애널리틱스를 방금 붙여 기준선이 0이다. 배포 후 이 변경의 효과를
분리해 보려면 티켓제 전/후 구간을 구분할 수 있어야 한다.

### 히어로 이미지는 바꾸지 않는다 (2026-07-28 결정)

카피라이팅 감사는 홈 히어로가 정물 사진(`/hero/concept_candles.jpg`)이라 이 서비스의
차별점인 월하비원·K-POP 뮤즈버스 아트가 홈에 한 번도 등장하지 않는다고 지적했다.
**이 권고는 채택하지 않는다.** 덱은 계속 추가되는 자산이라 특정 덱을 히어로에 박아 두면
덱이 늘 때마다 히어로를 다시 만들어야 하고, 먼저 나온 덱만 노출되는 편향도 생긴다.

덱 아트를 보여주는 자리는 히어로가 아니라 덱 소개 섹션(Phase 3)이 맡는다.
