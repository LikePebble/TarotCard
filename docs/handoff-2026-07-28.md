## ⚠️ 다음 작업자가 반드시 알아야 할 것

### 1. 마케팅 감사의 §1은 실행 전 스냅샷이다

`docs/marketing-audit-2026-07-28.md`의 "결정적 발견"은 실행 **전**에 쓰였다. 그 중
애널리틱스·폰트·sitemap·법적 문서·타이틀은 **이미 해소됐다.** §0.5를 먼저 읽을 것.

### 2. 그 감사는 기존 설계 문서를 읽지 않고 수행됐다

그래서 **이미 의도적으로 결정된 것을 결함으로 지목했다.** 철회된 권고:

- "덱 소개 섹션을 만들어야 한다" → `DeckInfoModal`로 이미 있었다
- "가격·구매 버튼 부재 = P0 결함" → 회귀 체크리스트가 지키는 의도된 결제 전 상태
- "`adFree` SKU 폐기" → 광고는 처음부터 계획된 수익 축(D15)
- "컬렉션/도감 용어 통일" → D8이 정의한 2층 구조. 통일하면 IA 재설계의 출발점이던
  용어 과부하가 재발한다
- "`<details>` 제거, 영어 원문 이동" → `card-detail-lore-design.md`가 지정한 구조

**구조적 원인은 `AGENTS.md`가 존재하지 않는 `CONTEXT.md`·`docs/adr/`을 가리킨 것**이었다.
지금은 고쳐서 `specs/2026-07-19-arcana-ia-design.md`(사실상의 ADR·용어집)를 가리킨다.

### 3. 게스트에게는 도감이 열리지 않는다 — 크롤러도 마찬가지

`src/lib/collection-access.ts:10`이 로그인 여부를 먼저 본다.

```ts
if (!signedIn) return { owns: false, encounters: new Set() };
```

소유 판정(`ownsDeck`)과 무관하게 비로그인 방문자는 전부 잠긴 화면을 본다. **출시 기념
프로모션이 AdSense 심사에 도움이 될 것으로 보았으나 사실이 아니었던 이유**가 이것이다.
심사자·크롤러가 볼 수 있는 것은 sitemap에 오른 카드 상세 78페이지뿐이다.

### 4. 하루 한도는 클라이언트 판정이다

진입 시와 기록 직전 두 번 보지만 둘 다 브라우저 localStorage 기준이다. 로그인 사용자가
서버 기록을 내려받기 전에 뽑으면 다른 기기의 사용량이 반영되지 않는다. **실제 강제는
서버 판정이 필요하고, 결제와 함께 설계해야 한다.**

### 5. 티켓제가 `ad_free` 상품의 핵심 가치를 무료로 나눠줬다

`arcana-ia-design.md:38-39`의 D14/D15는 **하루 3슬롯을 `ad_free` 보유자의 유료 혜택**으로
설계했다. 그런데 티켓제가 로그인한 무료 사용자에게 이미 3슬롯을 준다. AdSense 도입까지
확정된 지금 `ad_free`가 팔 수 있는 것은 "광고 제거" 하나뿐이다. **D15를 다시 설계해야
한다.**

### 6. 티켓제가 수집 기간을 크게 줄였다

78장 수집에 필요한 기대 뽑기는 쿠폰 수집가 문제로 약 385회. 시뮬레이션 20만 회 기준:

## 남은 일

### 출시 전 필수

- **출시 기념 프로모션 플래그를 끌 것.** `NEXT_PUBLIC_LAUNCH_PROMO_DECKS`가 켜진 채로
  유료 판매를 시작하면 "무료였는데 유료가 됐다"는 소비자 오인이 된다
- **탈퇴 처리 절차서.** 약관·방침이 **요청일부터 7일 이내** 처리를 약속했다. Supabase에서
  `readings`·`collection`·`journal_entries`·`entitlements`·`profiles` 행과 auth 사용자를
  지워야 하고 외래키 때문에 순서가 있다. 요청이 오기 전에 SQL로 정리해 둘 것
- 유료 판매에는 **사업자등록(간이과세자)** 이 필요하다. 간이과세자면 통신판매업 신고는 면제

### 사용자 작업 대기

`docs/release/analytics-ads-setup.md` 참조. GA4는 적용됐고 Search Console 소유 확인은
메타 태그 방식으로 바꿔 배포했다. AdSense는 **트래픽을 보고 나중에** 적용하기로 했다.

정본이고, 어긋남을 발견하면 그 자리에서 문서를 고쳐 둘 것.
