## 확정된 비즈니스 모델 (스펙에 상세)

- **리딩(운세)은 무료.** 파는 것은 **덱 소유(도감 완성)** + **광고 제거(`ad_free`)**. 성찰적 브랜드 톤·데일리 습관 루프를 지키려는 결정.
- **도감 = 소유 기반 갤러리**(그라인드 폐기). `수집(deckId) = 소유 ? 78 : 0`. 클래식은 모두에게 암묵 소유(78/78), 프리미엄은 0/78 → 구매 시 78/78.
- **B1:** 미소유 프리미엄은 로그인 사용자가 **뽑어서 아트는 보되 도감엔 안 쌓인다.** 구매가 전량 수집을 준다.
- 티어: 게스트(원카드·클래식·일기✕·광고) / 로그인무료(3장·전덱 뽑기·일기·광고) / +프리미엄 소유(그 덱 78) / +ad_free(3슬롯·광고제거).

## 하위 프로젝트 1이 실제로 넣은 것

- 순수 로직 `src/lib/entitlements.ts` — `ownsDeck`/`collectedCount(deckId, ent)`/`collectedSlugs`/`togetherDays`(store.ts)/`grantedWith`. 유닛테스트 완비.
- 도감 완성도가 **리딩 파생 → 소유 파생**으로 바뀜. `recomputeCollection`은 `recomputeEncounters`로 개명(만남 기록=CollectHistory용으로 역할 분리).
- MY의 "수집 n/78" → **"함께한 날"**(뽑은 날 distinct 수, 단위 없이 숫자만, 27년 헤드룸). `readings`에서 파생이라 서버 지표로 바로 쓰임.
- draw 결과의 "컬렉션에 추가되었습니다" 배너 은퇴.
- **스키마:** `entitlements(user_id, deck_id, granted_at, source)` + `profiles.ad_free`를 **아직 적용 안 한 `0001` 마이그레이션에 폴딩**. RLS·정책 포함.
- **서버 브리지(pull 전용):** `src/lib/sync/entitlements-remote.ts`의 `pullRemoteEntitlements(isStale)`·`grantDeck(deckId)`. pull은 `pusher.ts`의 로그인 병합 블록에서 `isStale` 가드로 호출. 지급은 서버 upsert(지금은 개발 버튼, 나중은 결제 웹훅 — 스키마 불변).

1. Supabase 프로젝트(서울 리전) → URL/anon key
2. Google·Kakao OAuth 등록
3. `supabase/migrations/0001_p1_foundation.sql` 실행 (**이제 entitlements·ad_free 포함**)
4. 루트에 `.env.local` 주입
