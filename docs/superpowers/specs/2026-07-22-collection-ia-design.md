# 컬렉션 IA 분리 설계 — 덱 목록 · 덱 도감 · 카드 상세

- 작성일: 2026-07-22
- 브랜치: `redesign/arcana`
- 상위 문서: [`2026-07-19-arcana-ia-design.md`](2026-07-19-arcana-ia-design.md) §4 사이트맵, D8·D9
- 범위: 컬렉션 탭의 라우트 3단 분리와, 그에 따라 갈라지는 덱 선택 상태 모델. 덱 상품화(설명·잠금·구매)는 P3이며 여기서는 자리만 만든다.

## 1. 배경

상위 IA는 컬렉션을 3단으로 규정한다 — 덱 목록 → 덱 상세(그 덱의 도감) → 카드 상세. 현재 구현은 2단이고 층이 어긋나 있다:

- `/collection` 한 화면에 **덱 탭과 78장 그리드가 섞여** 있다. D8이 정의한 "덱상세 = 상품페이지 + 그 덱 도감"이 들어갈 자리가 없다.
- 카드 상세는 `/collection/[slug]?deck=...`로, **덱을 쿼리스트링에 실어 나른다.** 덱이 둘일 때는 버텼지만 셋이 되면서 우회가 드러났다.
- 덱 선택이 `arcana.deck` **하나뿐**이라 "도감에서 구경 중인 덱"과 "리딩에서 뽑을 덱"을 구분하지 못한다. 컬렉션에서 덱 탭을 누르면 다음 리딩의 덱까지 바뀐다.

세 번째가 핵심이다. P3에서 아직 사지 않은 덱도 구경할 수 있어야 하므로, 구경과 사용의 분리는 언젠가 반드시 필요하다.

## 2. 확정된 설계 결정 (Decision Log)

| # | 결정 | 값 |
|---|---|---|
| C1 | 덱 상태 분리 | **기본 덱**(리딩에서 뽑을 덱, localStorage)과 **보는 덱**(도감에서 구경 중, URL 경로)을 나눈다 |
| C2 | 전환은 명시적으로 | 덱 도감을 열어도 기본 덱은 바뀌지 않는다. 바꾸려면 "기본 덱으로 설정"을 눌러야 한다 |
| C3 | 라우트 | `/collection` → `/collection/[deckId]` → `/collection/[deckId]/[slug]` |
| C4 | 진입 화면 | 컬렉션 탭은 **덱 목록**을 연다. 목록에서 **기본 덱을 맨 앞**에 놓아 평소 동선을 짧게 유지한다 |
| C5 | 알 수 없는 덱 | `[deckId]`가 등록된 덱이 아니면 `notFound()`. `deckById`의 클래식 폴백에 기대지 않는다 |
| C6 | 기본 덱 설정 지점 | **두 곳** — 컬렉션(덱 목록·덱 도감)과 MY(`/my/decks`) |
| | ↳ **번복(2026-07-22)** | MY 지점(`/my/decks`)을 제거해 컬렉션 두 곳만 남겼다. 실물을 놓고 보니 MY 쪽이 컬렉션과 하는 일이 완전히 같아 값을 더하지 않았다 |
| C7 | 쿼리 우회 제거 | `?deck=`을 없애고 덱은 경로에서만 읽는다 |
| C8 | 404 화면 | 이번 범위에서는 브랜드 톤만 맞춘 **자리표시자**만 만든다. 디자인된 오류 화면은 사용자가 별도 제작한다(§7 가이드) |

### C1을 택한 이유

대안은 URL 없이 지금처럼 상태만으로 덱을 전환하는 것이었다. 화면 수는 늘지 않지만 (a) 덱별 도감을 링크로 가리킬 수 없고, (b) P3 덱 스토어의 상품 페이지가 앉을 URL이 없으며, (c) "구경 = 사용"이라는 결합이 남아 안 산 덱을 미리 보여줄 수 없다. 지금 나누는 편이 나중에 나누는 것보다 싸다.

## 3. 상태 모델

```
기본 덱   localStorage "arcana.deck"   useSelectedDeck()      리딩 플로우 · 카드 뒷면
보는 덱   URL 경로 [deckId]            params                 덱 도감 · 카드 상세
```

`useSelectedDeck`은 시그니처를 바꾸지 않는다. **의미만 "기본 덱"으로 좁힌다.** 컬렉션 화면들이 이 훅을 더 이상 읽지 않게 되면서 결합이 끊어진다. 리딩 플로우(`/reading`, `/reading/focus`, `/reading/draw`)와 `CardBack`은 그대로 기본 덱을 쓴다.

리딩 결과(`/reading/[id]`)는 예외다. 그 리딩이 **어떤 덱으로 뽑혔는지**가 레코드에 `deckId`로 남아 있으므로, 기본 덱도 URL 덱도 아닌 **레코드의 덱**을 쓴다. 현행과 같다.

## 4. 라우트와 화면

### `/collection` — 덱 목록

덱마다 한 장의 카드: 뒷면 썸네일, 덱 이름, `n/78` 진행바, 기본 덱이면 `기본` 배지. **기본 덱을 배열 맨 앞으로 정렬**한다(원래 순서는 그 뒤에 유지).

카드 본체를 누르면 그 덱의 도감으로 이동한다. 카드 안의 "기본으로" 버튼은 이동 없이 기본 덱만 바꾼다 — 두 동작이 한 카드에 있으므로 버튼은 링크 안에 중첩하지 않고 형제로 배치한다(중첩 인터랙티브 요소는 접근성 위반이며 클릭 대상이 모호해진다).

전체 수집 요약(모든 덱 합산)은 P3 스토어와 함께 다룬다. 지금은 덱별 진행도만 보인다.

### `/collection/[deckId]` — 덱 도감

현재 `/collection` 화면의 본체(진행바·수트 필터·78장 그리드)가 그대로 옮겨온다. 달라지는 것:

- 덱 탭이 사라지고 **덱 이름**과 뒤로 가기가 자리한다.
- **"기본 덱으로 설정"** 버튼. 이미 기본이면 `기본 덱` 상태 표시로 바뀐다(버튼이 아무 일도 하지 않는 상태로 남지 않게).
- 그리드의 링크가 `/collection/[deckId]/[slug]`를 가리킨다.
- 수집 여부는 `store.collection[deckId]`로 판정한다(현행과 동일하나, deckId 출처가 URL로 바뀐다).

P3에서 덱 설명·잠금·구매가 이 화면 상단에 붙는다.

### `/collection/[deckId]/[slug]` — 카드 상세

현행 화면을 그대로 옮기고 `?deck=` 쿼리만 걷어낸다. 서버 컴포넌트와 `generateStaticParams`를 유지하되 덱 × 카드로 확장한다 — 3덱 × 78장 = **234개 정적 페이지**. 빌드 타임 산출이라 런타임 비용은 없다.

이전/다음 카드 순환은 **같은 덱 안에서** 돈다.

### `/my/decks` — 덱 관리

MY 허브의 진입 행(`일별 기록` 아래)에서 들어간다. 덱 목록과 **같은 카드 컴포넌트**를 쓰되 누르면 이동이 아니라 **기본 덱 선택**이다. 이 화면에서는 도감으로 넘어가지 않는다 — 여기는 "쓸 덱을 고르는 곳"이고, 구경은 컬렉션 탭의 일이다.

**번복(2026-07-22):** 이 화면은 제거되었다. 컬렉션 쪽 두 지점(덱 목록·덱 도감)이 같은 일을 이미 하고 있어 MY 쪽이 별도로 값을 더하지 않았다.

## 5. 컴포넌트

| 파일 | 책임 |
|---|---|
| `src/data/decks.ts` (수정) | `decksByDefaultFirst(defaultDeckId)` 추가 — 기본 덱을 맨 앞으로 정렬한 순수 함수(§8에서 테스트) |
| `src/components/DeckCard.tsx` (신규) | 덱 한 장의 표시 — 뒷면 썸네일·이름·진행도·기본 배지. 동작(이동/선택)은 주입받는다 |
| `src/app/collection/page.tsx` (재작성) | 덱 목록. 기본 덱 우선 정렬 |
| `src/app/collection/[deckId]/page.tsx` (신규) | 덱 도감. 기존 그리드·필터가 여기로 |
| `src/app/collection/[deckId]/[slug]/page.tsx` (이동) | 카드 상세 |
| `src/app/collection/[slug]/page.tsx` (삭제) | `[deckId]`와 자리가 겹쳐 공존 불가 |
| `src/app/my/decks/page.tsx` (신규) | 덱 관리 |
| `src/app/not-found.tsx` (신규) | 404 자리표시자 |

`DeckCard`가 표시만 맡고 동작을 주입받는 이유는, 컬렉션에서는 "이동"이고 MY에서는 "선택"이기 때문이다. 같은 모양을 두 벌 만들지 않는다.

## 6. 마이그레이션

- `/collection/[slug]`는 **삭제된다.** Next 라우팅에서 `[deckId]`와 같은 세그먼트를 차지해 공존할 수 없다.
- 내부 링크 2곳을 경로 방식으로 바꾼다 — `src/app/reading/[id]/page.tsx:88`과 `src/app/reading/draw/page.tsx:528`. 둘 다 `/collection/${slug}?deck=${deckId}` 형태로 그 리딩의 덱을 넘기고 있으므로, `/collection/${deckId}/${slug}`로 바꾸면 의미가 그대로 보존된다.
- 외부에 노출된 적이 없다(공유 기능 미구현, 미배포). 리다이렉트를 두지 않는다.
- localStorage 스키마는 그대로다. `arcana.deck`의 의미가 좁아질 뿐 키·값 형식이 바뀌지 않아 마이그레이션이 필요 없다.

## 7. 404 화면 — 이번 범위와 이후 가이드

이번에는 `src/app/not-found.tsx`에 **자리표시자**만 만든다: 앱 배경·서체를 따르고, 짧은 안내 문구와 홈/컬렉션으로 가는 링크만 둔다. 디자인은 하지 않는다.

이후 디자인된 오류 화면을 만들 때 알아야 할 것:

- **파일 위치가 곧 적용 범위다.** `src/app/not-found.tsx`는 전역이고, `src/app/collection/not-found.tsx`처럼 세그먼트 안에 두면 그 하위에서만 쓰인다. 컬렉션 전용 문구("그런 덱이 없습니다")를 쓰고 싶다면 후자를 추가한다 — 전역 파일을 조건 분기로 채우지 않는다.
- **`notFound()`를 호출한 위치의 레이아웃 안에서 렌더된다.** 즉 `src/app/layout.tsx`의 `<body>`, 폰트, `SyncBridge`가 그대로 살아 있다. 반대로 탭바(`TabBar`)나 상단 네비는 각 페이지가 직접 그리므로 404에는 **자동으로 붙지 않는다.** 필요하면 명시적으로 넣어야 한다.
- **`not-found.tsx`는 서버 컴포넌트다.** 상태나 이벤트 핸들러가 필요하면 클라이언트 컴포넌트를 분리해 끼워 넣는다.
- **예외로 인한 오류는 별개다.** `error.tsx`(세그먼트 오류 경계)와 `global-error.tsx`(루트 레이아웃까지 실패)는 `not-found.tsx`와 다른 파일이다. 404만 만들면 렌더 중 예외는 여전히 Next 기본 화면으로 떨어진다.
- 응답 상태 코드는 Next가 404로 맞춰 준다. 별도 설정이 필요 없다.

## 8. 테스트

라우팅과 화면은 유닛테스트하지 않는다(현행 vitest는 `environment: "node"`, DOM 없음). 순수 로직만 덮는다:

- **기본 덱 우선 정렬** — 순수 함수로 빼서 테스트한다. 기본 덱이 맨 앞이고 나머지는 원래 순서를 유지하는지, 기본 덱 id가 목록에 없을 때(삭제된 덱을 가리키는 경우) 원래 순서를 그대로 돌려주는지.
- 기존 `decks.test.ts`의 `deckById` 폴백 테스트는 그대로 둔다. C5는 폴백을 없애는 것이 아니라, 덱 페이지가 폴백에 **기대지 않고** 스스로 판정한다는 뜻이다.

나머지는 브라우저 확인: 덱 목록 정렬, 도감 이동, 기본 덱 설정이 리딩 덱에 반영되는지, 도감을 구경해도 기본 덱이 안 바뀌는지, 옛 URL이 404로 떨어지는지, MY에서 설정한 것이 컬렉션에 반영되는지.

## 9. 범위 밖

- 덱 상품화 — 설명·가격·잠금·구매·엔타이틀먼트 (P3)
- 전체 수집 요약(덱 합산) — P3 스토어와 함께
- 디자인된 404/500 화면 — 사용자가 별도 제작 (§7)
- `/my/purchases`, `/my/settings`, `/my/account` 분리 — 별도 작업
