# 게스트 수집 UX·덱 정보 모달·역방향 변형 재저작 설계 — 2026-07-25

## 목적

출시 하위 프로젝트 2(게스트 경계)·3(덱 스토어)의 일부를 앞당기고, 역방향 변형 텍스트의 품질 문제를 해소한다. 4개 항목:

1. 게스트 상태 카드 상세에 '미수집' 칩 + 로그인 유도(→ `/login` 신설)
2. 도감 '수집됨' 필터
3. 덱 카탈로그의 덱 정보(상품) 모달
4. 테마·포지션 역방향 변형 624건 재저작 (Codex 저작 + Opus 5 검수)

## 수집 모델 확인 (사용자 확인 완료)

- 게스트: 리딩만. 만남 기록은 로컬에 쌓이나 "수집"으로 치지 않는다.
- 회원: 카드별 만남 기록(`store.collection[deckId][slug]`)이 수집으로 인정.
- 구매(소유): 그 덱 도감 전체 해금(n/78은 소유 기준 — 기존 엔타이틀먼트 설계 유지).
- 게스트의 로컬 기록은 로그인 시 계정으로 머지되므로 "로그인하면 수집됩니다"가 문자 그대로 성립한다.

## 1. 미수집 칩 + `/login`

- `src/app/login/page.tsx` 신설. AccountCard의 로그인 UI(카카오/구글 버튼, 미설정 시 "준비 중", 로그인됨 상태 처리)를 공용 컴포넌트로 추출해 재사용. AccountCard는 추출된 컴포넌트를 쓰도록 리팩터(동작 불변).
- 카드 상세(`/collection/[deckId]/[slug]`)의 CollectHistory 영역:
  - **게스트(`!user`)**: entry 유무와 무관하게 `미수집` 칩 + "로그인하면 이 카드가 도감에 수집됩니다" 버튼 → `/login`. Supabase 미설정이어도 동일하게 노출(→ /login이 "준비 중"을 보여줌).
  - **로그인 상태**: 현행 유지(첫 수집/뽑은 횟수 또는 "아직 수집하지 않은 카드입니다").

## 2. '수집됨' 필터

- DeckCatalogPage(`/collection/[deckId]`) FILTERS 배열에 `{ id: "collected", label: "수집됨" }` 추가(펜타클 뒤).
- 기준: `store.collection[deckId][slug]` entry 존재(만남 기록).
- 결과 0건이면 그리드 대신 기존 배너 스타일로 "아직 수집한 카드가 없습니다." 안내. 게스트면 로그인 유도 한 줄 병기(→ `/login`).
- 수집됨 필터의 카드 렌더는 기존 그리드와 동일 규칙(소유 여부에 따라 앞면/뒷면).

## 3. 덱 정보 모달

- `deck.json` 확장: `description: string[]`(문단 배열), `price?: number`, `productImages?: string[]`.
  - 첫 이미지 = 800×1360(10:17) 규격 상품 이미지. 이후 이미지들은 모달 안에서 세로 스크롤로 이어 노출(선택).
  - 이미지 경로 규약: `public/decks/<id>/product/NN.webp`. 파일이 아직 없으므로 규약만 잡고, 없으면 "이미지 준비 중" 플레이스홀더 블록.
  - 클래식은 deck.json이 없으므로 클래식용 정보는 코드 상수로 동일 구조 제공.
- `DeckInfoModal` 컴포넌트(클라이언트): 10:17 이미지 영역 + 소개 문구 + 가격. 프리미엄 덱 가격은 미정이므로 "출시 예정" 표기. 닫기 버튼·바깥 클릭 닫기·스크롤 잠금.
- 진입점: 덱 카탈로그 헤더 "기본 덱으로 설정" 옆 "덱 정보" 텍스트 버튼(기본 덱 상태일 때도 노출).
- 임시 카피: 3개 덱 소개 문구를 브랜드 톤(성찰적 존댓말)으로 초안 작성. 나중에 문구·가격·이미지만 교체하면 되는 구조가 목표.

## 4. 역방향 변형 624건 재저작

- **범위**: 테마 역방향 390건(78×5) + 포지션 역방향 234건(78×3). 정본 `reversed.ts` 78건은 유지.
- **문제**: 현행 변형이 정본의 단어·문형을 답습해 테마·포지션 고유 맥락이 약하다.
- **지침**:
  - 정본은 의미의 씨앗으로만 쓰고 워딩·문형 답습 금지.
  - `docs/reversed-variants-basis-2026-07-23/`의 카드별 Waite·Mathers 근거 키워드를 테마(사랑/일/나/건강/금전)·포지션(과거/현재/미래)의 구체 상황으로 직접 투영해 새로 저작.
  - 분량·존댓말·겁주지 않는 톤·문장 수 등 기존 규약 유지. 데이터 구조·키는 불변(텍스트만 교체).
- **파이프라인** (사용자 지정):
  - **저작: Codex 워커** — 파일 충돌 없게 테마·포지션 파일 단위 분할(구조 실측은 플랜에서). Codex 샌드박스 제약: 웹 불필요(근거 JSON 로컬), 커밋·테스트 불가 → 검증·커밋은 어드바이저.
  - **검수: Opus 5** — ① 정본 대비 워딩 독립성(핵심) ② 테마·포지션 반영도 ③ Waite·Mathers 근거 정합 ④ 톤. 지적 반영 후 재검수, 어드바이저 커밋.
- **실행 구조**: 이중 트랙 — 재저작 Codex 잡을 먼저 발사하고, 도는 동안 UI 3건을 SDD로 진행(벽시계 최소화).

## 테스트

- `/login`: 렌더 + 미설정 상태 문구(수동/브라우저 검증 중심, 로직 테스트는 추출 컴포넌트 분기).
- 수집됨 필터: 필터 로직 단위 테스트(entry 있는 slug만), 0건 빈 상태.
- 덱 정보: deck.json 파싱 확장의 타입·기본값 테스트.
- 재저작: 기존 데이터 파일 형식 테스트가 있으면 유지 통과, 없으면 키 전수(624) 검증 추가. 실행은 `./node_modules/.bin/vitest run` / `tsc --noEmit`, dev 서버 중 `npm run build` 금지.
