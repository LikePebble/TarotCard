# IP 기반 영문 현지화 완성 계획

## 목표와 완료 기준

- Vercel 국가 헤더가 `KR`이면 한국어, 그 외와 미확인이면 영어를 같은 URL에서
  제공한다. 선택 UI·쿠키 기반 언어 고정·언어 URL 접두사는 만들지 않는다.
- 영어 요청의 사용자 노출 화면에는 한국어 UI·해석·법적 본문이 남지 않는다.
- 카드 아트 안에 구워진 한글은 별도 아트 파이프라인 의존성으로 기록하고 앱 코드로
  덮어쓰지 않는다.

## 실행 순서

1. **런타임 기반** — locale 판별, 요청 전달, HTML 언어, SEO 메타, 캐시 분리를
   유지한다. 순수 판별 테스트와 KR/비KR HTTP 검증으로 확인한다.
2. **UI 표면** — 홈·리딩·수집·로그인·MY·일기·문의·공유·팝업·오류를 공통
   로케일 API로 전환한다. 영어 렌더 경로에서 한국어 문자열을 정적 검사한다.
3. **콘텐츠 정본** — 78장 기본/역방향, 5개 주제, 3개 포지션, lore, 덱 정보,
   약관·방침을 영문 데이터로 작성한다. 한국어 정본의 비단정적 의미를 보존하며,
   원문을 대체하거나 한국어 데이터를 수정하지 않는다.
4. **외부 검증** — 구현이 끝난 뒤 별도 검증 계획서에 국가별 렌더링, 로그인/게스트,
   리딩 방향·주제·포지션, 법적 문서, SEO/공유, 캐시 혼선을 포함한다.

## 저작 규칙

- 영어는 기존 `cards.en`을 기본 해석의 출발점으로 쓰되, 주제·포지션·lore는
  카드별 의미를 보존한 독립 문장으로 채운다. 임시 템플릿 문장은 출시 전 정본이
  될 수 없다.
- 법적 문서는 한국어 현행판의 번역본이며, 금액·사업자·시행일·권리 범위를
  바꾸지 않는다. 공개 전 법무/운영 검토를 외부 검증 항목으로 남긴다.
- 각 단계마다 `tsc`, 관련 Vitest, 한국어 누락 탐지, 실제 Preview 국가별 확인을
  실행한다. dev 서버가 실행 중이면 build는 돌리지 않는다.
