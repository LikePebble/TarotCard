# UI 개선 배치 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 결과 화면 테마 배치 정리, 3장 결과에서 작은 카드 줄·스와이프 철회, 역방향 카드 도입, draw 화면의 카드 더미 위치·셔플 전환 다듬기.

**Architecture:** Task 1·2는 결과 화면, Task 3은 데이터에서 화면까지 관통, Task 4·5는 draw 화면 연출이다. Task 2가 어제 만든 것을 일부 걷어내므로 Task 3보다 먼저 한다 — 걷어낸 자리에 역방향 표시를 얹는 편이 순서가 짧다.

**Tech Stack:** Next.js 15 App Router, React 19, TypeScript, Tailwind v4, `motion/react`, Vitest 2 (`environment: "node"`).

### Task 1: 테마(포커스) 문구를 하단으로

**해석에 주의.** 사용자 요청은 "테마(사랑 등)는 줄바꿈해서 하단에 위치"다. 지금 테마 라벨은 **머리말에 인라인으로** 붙어 있다 — 3장 결과는 `과거 · 현재 · 미래 오늘 하루`처럼 구분자도 없이 이어져 읽기 어색하다([`ReadingResult.tsx`](../../../src/app/reading/ReadingResult.tsx)의 두 머리말). 하단에는 이미 테마 해석 블록이 따로 있다.

**이 계획의 해석:** 머리말에서 인라인 테마 라벨을 빼고, 테마는 **하단 블록 한 곳**으로 일원화한다. 하단 블록은 줄바꿈된 자기 영역을 갖는다. 이 해석이 틀렸다면 되돌리기 쉬운 변경이다.

- [x] **1a.** `OneCardResult` 머리말에서 `· {focusLabelOf(focus)}` 인라인 부분을 제거한다. `오늘의 카드`만 남는다.
- [x] **1b.** `ThreeCardResult` 머리말도 같게 — `과거 · 현재 · 미래`만 남긴다.
- [x] **1c.** 하단 테마 블록은 두 화면 모두 유지하되, `themeParagraph`가 없을 때도 **테마 라벨만은 하단에 보이게** 한다(지금은 문단이 없으면 블록 전체가 사라져 무슨 테마로 뽑았는지 알 수 없다).
- [x] **1d.** `npx tsc --noEmit` · `npm test` 통과 확인.

### Task 3: 역방향 카드

**지금 상태.** `Orientation` 타입(`"upright" | "reversed"`)과 저장·서버 동기화 자리는 있는데 [`draw/page.tsx:187`](../../../src/app/reading/draw/page.tsx)이 모든 카드를 `upright`로 못 박고, **`orientations`를 읽어서 그리는 코드가 하나도 없다.**

**콘텐츠 제약(중요).** [`src/data/ko.ts`](../../../src/data/ko.ts)에는 카드당 해석이 하나뿐이다. **역방향 해석문 78개가 존재하지 않는다.** 이 배치에서 그것을 지어내지 않는다 — 해석문은 사용자가 소유할 콘텐츠다.

**이 배치의 범위:** 방향을 뽑고, 아트를 뒤집고, 역방향임을 화면에 분명히 표시하고, **공통 안내 문단** 하나를 붙인다. 카드별 역방향 해석문은 별도 작업으로 남긴다.

- [x] **3a.** `src/lib/orientation.ts`(신규)에 순수 함수를 둔다: `pickOrientations(count, rand): Orientation[]`. `rand`는 `() => number`를 주입받아 테스트 가능하게 한다. 확률은 **역방향 50%**.
- [x] **3b.** `src/lib/orientation.test.ts`(신규). 주입한 `rand`로 결정적으로 검증한다(전부 정방향/전부 역방향/혼합, 길이).
- [x] **3c.** `draw/page.tsx`의 `record()`에서 `orientations: slugs.map(() => "upright")`를 `pickOrientations(slugs.length, ...)`로 바꾼다. 난수는 이 파일에 이미 있는 보안 난수 경로를 따른다 — `uid()`가 `crypto.getRandomValues` 폴백을 쓰는 이유(비보안 출처에서 `crypto.randomUUID`가 없음)를 그대로 존중할 것.
- [x] **3d.** `CardArt`에 `orientation?: Orientation` prop을 추가한다. `"reversed"`면 이미지를 **180도 회전**시킨다(`rotate-180`). 기본값은 `"upright"`이라 기존 호출부는 무변경.
- [x] **3e.** `CardArtViewer`에도 같은 prop을 통과시킨다(트리거와 전체화면 오버레이 **둘 다** 뒤집혀야 한다).
- [x] **3f.** 결과 화면 두 곳에서 리딩의 `orientations[i]`를 카드에 넘긴다. `ThreeCardResult`는 선택된 인덱스의 방향을 쓴다.
- [x] **3g.** 역방향일 때 카드 이름 옆이나 아래에 **`역방향` 표시**를 붙인다(금색 소형 배지). 표시가 없으면 사용자는 아트가 왜 뒤집혔는지 알 수 없다.
- [x] **3h.** ~~역방향일 때 하단에 **공통 안내 문단** 하나를 덧붙인다. 카드별 해석문은 만들지 않는다.~~

  **범위가 바뀌었다.** 작업 중 사용자가 역방향 해석문을 직접 조달하라고 했다. A.E. Waite, *The Pictorial Key to the Tarot*(1911)의 각 카드 `Reversed` 점의를 근거로 78장 ko+en을 새로 써 `src/data/reversed.ts`에 넣고, 공통 문구는 폴백으로만 남겼다.
- [x] **3i.** 결과 컴포넌트는 `orientations`가 **비어 있거나 길이가 모자란 리딩**(레거시·마이그레이션 기록)에서도 깨지지 않아야 한다. 없으면 `upright`로 본다.
- [x] **3j.** `npx tsc --noEmit` · `npm test` 통과 확인.

### Task 4: draw 화면 카드 더미 위치를 1장과 통일

**증상.** 3장 셔플일 때 카드 더미가 위쪽에 붙어 있고, 뽑을 때 카드가 잘린다.

**원인 후보(조사해 둔 것).** [`draw/page.tsx:418-422`](../../../src/app/reading/draw/page.tsx)에서 부채꼴 컨테이너 클래스가 스프레드별로 갈린다. 3장은 `fan-three mt-4 h-[250px] flex-none overflow-hidden lg:h-[430px] lg:overflow-visible`이다. **모바일에서 고정 높이 250px + `overflow-hidden`** 조합이 잘림의 직접 원인일 가능성이 높다. 1장 쪽 클래스와 비교해서 맞춘다.
또한 3장에는 상단에 선택 슬롯 줄(같은 파일 338행 부근)이 있어 더미가 아래로 밀리거나 위로 붙는다 — 이것까지 함께 봐야 한다.

- [x] **4a.** 브라우저에서 1장·3장 draw를 나란히 열어 더미의 화면상 위치와 잘림을 **실제로 확인**한다. 추측으로 클래스를 바꾸지 말 것.
- [x] **4b.** 3장 더미가 1장과 같은 세로 위치에 오도록 맞추고, 뽑을 때 카드가 잘리지 않게 한다.
- [x] **4c.** 3장의 선택 슬롯 줄이 여전히 제 역할을 하는지 확인한다(뽑은 카드가 슬롯으로 이동하는 연출).
- [x] **4d.** 모바일(375px)과 데스크톱 양쪽에서 확인한다.
- [x] **4e.** `npx tsc --noEmit` · `npm test` 통과 확인.

### Task 5: 셔플 → 부채꼴 전환의 깜빡임 제거

**증상.** 섞는 애니메이션의 마지막 프레임에서 부채꼴 더미로 넘어갈 때 자연스럽게 이어지지 않고 단순히 깜빡이며 바뀐다.

**단서.** 셔플은 `is-shuffling` 클래스를 붙였다 떼는 방식이다(같은 파일 422행, CSS는 `src/app/globals.css`). 클래스가 떨어지는 순간 변환값이 급격히 되돌아오면 한 프레임 튀어 보인다.

- [x] **5a.** 먼저 **현재 동작을 브라우저에서 관찰**한다. 어느 시점에 무엇이 튀는지 말로 적을 수 있어야 고칠 수 있다.
- [x] **5b.** 전환이 이어지도록 고친다. 방법은 구현자 판단에 맡긴다 — 셔플 종료를 트랜지션으로 감싸든, 지속 시간을 늘리든, 마지막 상태를 부채꼴 상태와 일치시키든. **다만 무엇을 왜 골랐는지 주석으로 남길 것.**
