# UI 개선 배치 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 결과·컬렉션·리딩 선택 화면의 네 가지 UI 개선. 3장 결과 화면 재설계는 규모가 달라 이 배치에서 빼고 별도로 다룬다.

**Architecture:** 네 변경은 서로 독립적이다. 다만 Task 4(전체화면 뷰어)가 결과 화면 레이아웃을 건드리므로, 곧 이어질 3장 결과 재설계와 겹치는 부분이 생긴다. 뷰어 배선 자체는 재설계 후에도 살아남는 형태로 만든다.

**Tech Stack:** Next.js 15 App Router, React 19, TypeScript, Tailwind v4, Vitest 2 (`environment: "node"`).

## Global Constraints

- **`npm run build`를 돌리지 않는다** — dev 서버가 떠 있으면 `.next`가 깨진다. `npx tsc --noEmit`과 `npm test`로 확인한다.
- 기존 테스트 66개는 계속 통과해야 한다.
- 한국어 주석, 짧게, 왜 그런지 위주. 2-space, 큰따옴표, Tailwind v4.
- 테스트 환경은 `node`다. `window`·DOM이 없다. 새 테스트는 순수 함수만 대상으로 한다.
- DRY, YAGNI, 잦은 커밋.

### Task 1: 뽑기 직후 화면에도 일기 링크

**이것은 어제 결정의 번복이다.** [`2026-07-22-post-p1.1-cleanup-batch.md`](2026-07-22-post-p1.1-cleanup-batch.md) Task 3은 일기를 회고로 보고 진입점을 `/reading/[id]`에만 두었다. 사용자가 뽑기 직후에도 노출하기로 했다. 계획서에 번복을 남기되 원래 근거는 지우지 않는다.

- [x] **1a.** [`src/lib/store.ts:177`](../../../src/lib/store.ts)의 `recordReading` 반환을 `ArcanaStore`에서 `{ store: ArcanaStore; record: ReadingRecord }`로 넓힌다. 호출자는 draw 한 곳뿐이고 직접 테스트는 없다(테스트는 순수 함수 `withReadingRecorded`를 본다).
- [x] **1b.** draw의 `record` 콜백이 반환된 레코드를 state에 담는다. `setCount`는 그대로 `result.store`를 쓴다.
- [x] **1c.** `OneCardResult`·`ThreeCardResult`의 `actions`에 일기 링크를 추가한다. `/reading/[id]`와 **같은 라벨 규칙**을 쓴다 — `useJournal()`로 그날 일기 유무를 보고 `이날의 일기 보기` / `이날의 일기 쓰기`.
- [x] **1d.** 라벨 계산이 두 화면에 중복된다. `src/app/reading/JournalLink.tsx`(신규, 클라이언트)로 뽑아 `{ localDate }`만 받게 하고 `/reading/[id]`도 이걸 쓰도록 바꾼다. 그 파일이 `useJournal` 구독과 라벨 규칙을 혼자 안다.
- [x] **1e.** `npx tsc --noEmit` · `npm test` 통과 확인.

### Task 2: 카드 상세의 이전/다음을 수집한 카드로 제한

**무엇이 문제인가.** [`src/app/collection/[deckId]/[slug]/page.tsx:62-64`](../../../src/app/collection/[deckId]/[slug]/page.tsx)가 78장 전체 순서로 이전/다음을 만든다. 도감 그리드는 수집한 카드만 링크하는데, 상세에 한 번 들어가면 화살표로 미수집 카드를 전부 넘겨볼 수 있다. 수집이라는 장치가 무의미해진다.

**제약.** 이 페이지는 서버 컴포넌트고 `generateStaticParams`로 234장을 빌드 타임에 굽는다. 수집 여부는 localStorage에만 있어 서버가 알 수 없다. **네비게이션만** 클라이언트 컴포넌트로 떼어낸다. 페이지 나머지는 정적 생성 그대로 둔다.

**동작:** 수집한 카드만 순회한다(건너뛰기). 비활성화가 아니라 건너뛰기인 이유는, 초반에는 수집이 드물어 비활성 화살표만 계속 보이는 화면이 되기 때문이다.

- [x] **2a.** `src/lib/collection-nav.ts`(신규)에 순수 함수를 만든다:
  ```ts
  export function neighborSlugs(
    orderedSlugs: string[],     // cards 순서
    collected: Set<string>,
    current: string,
  ): { prev: string | null; next: string | null }
  ```
  규칙:
  - 수집 카드가 0장이면 둘 다 `null`.
  - 수집 카드가 1장이고 그게 현재 카드면 둘 다 `null`(자기 자신으로 도는 링크는 만들지 않는다).
  - 현재 카드가 수집 목록에 있으면 그 목록 안에서 앞뒤로, 끝에서 순환한다.
  - **현재 카드가 수집 목록에 없으면**(URL 직접 진입) 전체 순서 기준으로 앞쪽의 마지막 수집 카드와 뒤쪽의 첫 수집 카드를 고른다. 없으면 순환해서 채운다.
- [x] **2b.** `src/lib/collection-nav.test.ts`(신규). 위 네 규칙 + 순환 경계를 덮는다. 순수 함수라 `node` 환경에서 돈다.
- [x] **2c.** `src/components/CollectedCardNav.tsx`(신규, 클라이언트). props는 `{ deckId, slug }`. `useArcanaStore()`로 수집 집합을 만들고 `neighborSlugs`를 부른다. 링크 마크업은 현재 페이지의 것을 그대로 옮긴다(`CaretLeft`/`CaretRight` + 한글명 + 영문명).
- [x] **2d.** **마운트 전 레이아웃 흔들림을 막는다.** `store`가 `null`인 동안에도 바깥 컨테이너(`border-t` 행)는 같은 높이로 자리를 잡아야 한다. 안쪽만 비운다.
- [x] **2e.** 상세 페이지에서 `prev`/`next` 계산과 그 마크업을 걷어내고 `<CollectedCardNav deckId={deck.id} slug={card.slug} />`로 교체한다. 이제 안 쓰는 import(`prevNameKo` 등 지역 변수 포함)를 정리한다.
- [x] **2f.** `npx tsc --noEmit` · `npm test` 통과 확인.

**남는 구멍(의도적):** URL을 직접 치면 미수집 카드 상세는 여전히 열린다. 사용자가 "이전/다음으로 새는 것"을 막기로 한 범위다. 정적 생성 페이지에 진입 차단을 붙이면 깜빡임이 생겨 따로 판단하기로 했다.

### Task 4: 결과 화면에서 카드를 눌러 전체화면으로

**막는 것:** 뷰어의 트리거 버튼이 상세 페이지에 맞춘 크기 클래스를 하드코딩하고 있다(`w-[216px] lg:w-full`). 그대로 쓰면 결과 화면의 카드 크기가 바뀐다.

- [x] **4b.** `OneCardResult`의 카드 박스를 `CardArtViewer`로 바꾼다. 지금 크기(`w-[248px] lg:max-w-[400px]`)와 그림자를 `triggerClassName`으로 넘겨 겉모습을 유지한다.
