# 덱 캔버스 제작 가이드

테마 덱의 카드 아트 위에 씌우는 덱 공통 캔버스(프레임 + 카드명 + 숫자) 제작 기준.
아트는 텍스트 없는 풀블리드 일러스트로 제작하고, 캔버스는 그 위에 레이어로 얹는다.

**선별 적용 원칙**: 캔버스 오버레이는 전 카드 일괄 적용이 아니다. 이미 프레임이
완성된 상태로 제작된 카드는 그대로 사용하고, 프레임 없는 카드에만 덱 공통
캔버스를 씌운다. 카드별 적용 여부는 덱 메타데이터(`deck.json`)의 `canvas` 필드로
선언한다 (섹션 5 참조).

## 0. 카드별 캔버스 모드

| 모드 | 의미 | 앱 동작 |
|---|---|---|
| `baked` | 프레임(과 텍스트)이 아트에 이미 포함된 완성본 | 그대로 표시. 프레임/텍스트 오버레이 없음 |
| `overlay` | 텍스트 없는 풀블리드 아트 | 덱 공통 프레임 + 카드명/숫자 오버레이 적용 |
| `frame-only` | 프레임은 포함, 텍스트는 없음 (예외 케이스) | 텍스트 오버레이만 적용 |

- 한 덱 안에 `baked`와 `overlay`가 섞여도 된다. 단, 최종 화면에서 프레임 문법과
  타이포가 시각적으로 통일되어 보이는지가 검수 기준 (섹션 6 체크리스트에 포함)
- `baked` 카드의 프레임은 이 가이드의 프레임 문법(섹션 3)과 텍스트 위치(섹션 4)를
  기준으로 제작되어야 두 모드가 나란히 놓여도 이질감이 없다

## 1. 구조: 3층 레이어

```
[3] 텍스트 레이어   카드명(한/영), 로마 숫자 - 앱이 런타임 렌더링
[2] 프레임 레이어   덱 공통 캔버스 템플릿 PNG (중앙 투명)
[1] 아트 레이어     풀블리드 일러스트 (텍스트 절대 굽지 않음)
```

- 앱 안에서는 [2][3]을 CSS/컴포넌트로 렌더링한다. 한/영 병기와 타이포 일관성을 앱이 보장
- 공유 이미지, 스토어 배너 등 앱 밖 산출물이 필요할 때만 3층을 합성(export)한다

## 2. 아트 레이어 규격

| 항목 | 기준 |
|---|---|
| 비율 | 1 : 1.7 (앱 카드 비율 2/3.4와 동일) |
| 원본 해상도 | 1200 x 2040 px 이상 (권장 1500 x 2550) |
| 포맷 | 원본 PNG 보관, 서비스용은 WebP/JPEG 변환 |
| 텍스트 | 금지. 글자, 워터마크, 서명 모두 없음 |
| 모서리 | 사각형으로 제작 (라운딩 12px은 앱이 마스킹) |

### 세이프존 (1200 x 2040 기준)

```
+--------------------------------+
|        상단 170px: 숫자존       |  로마 숫자가 놓임. 핵심 요소 배치 금지
|  +--------------------------+  |
|  |                          |  |
|  |      코어존 (자유)        |  |  좌우 72px: 프레임존
|  |   주인공, 핵심 상징 배치   |  |  프레임 장식에 가려질 수 있음
|  |                          |  |
|  +--------------------------+  |
|       하단 300px: 타이틀존      |  카드명 + 스크림이 덮임
+--------------------------------+
```

- 주인공의 얼굴, 손, 핵심 상징물(장미, 봇짐 등)은 코어존 안에
- 하단 300px에는 "가려져도 되는" 요소만 (지면, 그림자, 배경)
- 좌우 72px 안쪽으로 동물, 소품의 얼굴이 걸치지 않게 (예: 바보 카드의 개)

## 3. 프레임 레이어 (덱 공통 템플릿)

덱마다 1개의 `frame.png`를 만들고 78장 전체에 동일 적용한다.

- 캔버스와 동일 해상도, 중앙은 투명
- 기본 문법 (아르카나 공통, 앱 카드백과 통일):
  - 외곽 2px 골드 라인 `#C9A24B` 불투명도 35%
  - 내곽 1px 골드 라인 불투명도 22%, 외곽에서 14px 안쪽
  - 하단 스크림: 높이 300px, `#14110D` 불투명도 0% -> 65% 세로 그라디언트 (카드명 가독성용)
- 덱별 변주 허용 범위: 프레임의 질감/문양/색조 (예: 달빛 덱은 은청색 라인 + 매화 문양 코너)
- 변주 불가: 레이아웃 그리드(세이프존, 텍스트 위치)는 모든 덱이 동일하게 유지. 앱 오버레이 로직이 덱을 가리지 않기 위함

## 4. 텍스트 레이어

| 요소 | 위치 | 스타일 |
|---|---|---|
| 로마 숫자 (메이저) | 상단 중앙, 위에서 60px | Noto Serif KR SemiBold, 골드 소프트 `#E0C078` |
| 카드명 한글 | 하단 중앙, 아래에서 150px | Noto Serif KR SemiBold 크게 |
| 카드명 영문 | 한글명 바로 아래 | Wanted Sans Regular 작게, 뮤티드 `#9A8F7C` |

- 마이너 아르카나는 숫자 생략, 카드명만 ("컵 에이스 Ace of Cups")
- 모든 텍스트는 앱/합성 파이프라인이 그린다. 디자이너는 위치만 지키면 됨

## 5. 파일 규칙

```
public/decks/<deckId>/art/<slug>.webp   아트 (overlay 모드: 풀블리드 / baked 모드: 완성본)
public/decks/<deckId>/frame.png         덱 공통 프레임 (overlay 카드가 1장이라도 있으면 필수)
public/decks/<deckId>/deck.json         덱 메타 + 카드별 캔버스 모드
```

`deck.json` 예시:

```json
{
  "id": "moonlight",
  "nameKo": "달빛 덱",
  "canvasDefault": "overlay",
  "canvasOverrides": {
    "the-fool": "baked",
    "the-magician": "baked"
  }
}
```

- `canvasDefault`: 덱의 기본 모드. `canvasOverrides`: 예외 카드만 명시
- 앱과 합성 파이프라인 모두 이 필드를 읽어 오버레이 적용 여부를 결정한다
- slug는 `src/data/cards.ts`와 동일 (the-fool, ace-of-cups ...)
- 기본덱(클래식)은 전 카드 `baked`(캔버스 포함 스캔본)인 덱의 사례다

## 6. 검수 체크리스트 (카드당)

공통:

- [ ] 비율 1:1.7, 폭 1200px 이상
- [ ] 손가락, 장신구 등 디테일 붕괴 없음 (AI 생성 시 확대 검수)
- [ ] 카드 정체성 도상 충족 (해당 카드의 전통 상징 최소 3개)
- [ ] 덱 시그니처 규칙 준수 (예: 달빛 덱이라면 달의 위치/형태 규칙)
- [ ] deck.json에 캔버스 모드가 올바르게 선언됨

`overlay` 카드:

- [ ] 이미지 안에 글자/워터마크 없음
- [ ] 핵심 상징이 코어존 안에 있고, 세이프존에 걸친 요소 없음
- [ ] 하단 300px에 스크림을 얹었을 때 가려지는 핵심 요소 없음

`baked` 카드:

- [ ] 프레임이 섹션 3의 문법(라인 굵기, 색, 여백)과 일치
- [ ] 카드명/숫자 위치와 서체가 섹션 4 기준과 일치 (한/영 병기 포함)
- [ ] overlay 카드와 나란히 놓았을 때 이질감 없음 (컬렉션 그리드에서 비교)

## 7. 첫 번째 검수 사례: 바보 The Fool (달빛 덱 후보)

- 도상: 봇짐 막대, 흰 장미, 흰 개, 절벽, 하늘을 향한 시선 - 통과
- 비율: 1:1.716 - 상하 미세 크롭으로 1:1.7 맞춤
- 지적 사항:
  1. 달 + 태양 공존: '달 The Moon' 카드와 도상 혼선 여지. 덱 시그니처(전 카드 달 등장)로 규칙화할지 결정 필요
  2. 개가 우측 프레임존에 걸침: 씌웠을 때 얼굴 일부 가림 가능. 원본에서 5% 안쪽으로 리프레이밍 권장
  3. 전달본 800px 폭: 1200px+ 원본 확보 필요
